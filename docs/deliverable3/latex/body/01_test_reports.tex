\textbf{How to re-run.}

\begin{enumerate}
\item Unit and integration: \texttt{cd backend} then \texttt{pytest} (about 26 s). Add \texttt{-\allowbreak{}-\allowbreak{}cov=\allowbreak{}app -\allowbreak{}-\allowbreak{}cov-\allowbreak{}branch} for coverage.
\item System: \texttt{bash testing/\allowbreak{}start\_\allowbreak{}stack.\allowbreak{}sh}, then \texttt{python testing/\allowbreak{}system\_\allowbreak{}tests.\allowbreak{}py}.
\item Adversarial: \texttt{bash testing/\allowbreak{}start\_\allowbreak{}stack.\allowbreak{}sh} again, then \texttt{python testing/\allowbreak{}adversarial\_\allowbreak{}tests.\allowbreak{}py}.
\item Concurrency: \texttt{bash testing/\allowbreak{}start\_\allowbreak{}stack.\allowbreak{}sh} again, then \texttt{python testing/\allowbreak{}concurrency\_\allowbreak{}tests.\allowbreak{}py}.
\item Failure and recovery: \texttt{python testing/\allowbreak{}failure\_\allowbreak{}recovery\_\allowbreak{}tests.\allowbreak{}py} (it starts its own copy; see \texttt{testing/\allowbreak{}README.\allowbreak{}md}).
\end{enumerate}

Steps 2 and 3 need Linux, macOS or WSL, a built frontend and Playwright. \texttt{testing/\allowbreak{}README.\allowbreak{}md} lists the one-time setup. \texttt{start\_\allowbreak{}stack.\allowbreak{}sh} drops and recreates its own test database, so never point it at real data.
